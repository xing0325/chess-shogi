## 1. 概述

一个浏览器在线对战游戏,把**国际象棋**和**将棋**放进同一张 **9×9** 棋盘对弈,并融入少量**中国象棋**视觉元素(楚河汉界)。一方执国象,一方执将棋,规则冲突处按本规格抚平。

- 联网形态:**玩家大厅**——能看到在线玩家列表、开放房间;可建房等人,也可在大厅直接邀请某个在线玩家;对方接受后开局。
- 第一版范围:**玩法 + 美术一起做**(不是纯原型,也不是纯纸面)。
- 美术素材:网上找 CC0 免费材质;个别想要更精的图可转 Codex + image-2 生成。

## 2. 技术架构

| 部分 | 选型 | 说明 |
|---|---|---|
| 前端 | Vite + React + TypeScript | 棋盘用 CSS Grid + 图片棋子,便于贴材质/换皮肤 |
| 后端 | Node + Express + Socket.IO + TS | 大厅在线状态、房间、邀请、实时走子同步 |
| 规则引擎 | `shared/` 纯 TS 模块 | 前后端共用一份走子/吃子/判定逻辑,**服务器为权威** |
| 存储 | v1 全内存(在线玩家 + 进行中对局) | 不接数据库;以后要排行榜再加 |
| 部署 | Railway(单服务托管静态前端 + socket) | 每次 push 给预览链接 |

项目结构(monorepo):

```
chess-shogi/
  client/    # Vite + React 前端
  server/    # Node + Socket.IO 后端
  shared/    # 规则引擎 + 类型(前后端共用)
  docs/
```

设计原则:规则引擎是纯函数模块(输入局面+走法 → 输出新局面/合法性),不依赖网络或 UI,可独立单测。服务器只调用规则引擎做权威校验。

## 3. 棋盘与初始布局(9×9)

- 文件 a–i(9 列),行 1–9。
- **将棋方在下半盘(行 1–4,木纹风格)**;**国象方在上半盘(行 6–9,黑白格风格)**。
- **第 5 行 = 楚河汉界**(渡口流水视觉,可正常走子,见 §6)。

- 两边各占 4 行 + 中间 1 行河界,视觉对称;兵线之间隔 4 个空行,留调度空间(数值后续可微调)。

## 4. 走子与吃子

1. 国象子按国际象棋规则走;将棋子按将棋规则走。各管各的走法。
2. 吃子:走到对方棋子所在格即吃掉它。
3. 国象的王车易位、兵的两格首动、吃过路兵等标准规则保留(易位需两个王分别判定,见 §5 备注)。

## 5. 胜负判定(双 King 机制)

国象方有 **2 个 King**,将棋方有 1 个王(玉)。

- **还有 2 个 King 时**:King 当作普通棋子,**可以被直接吃掉**,不触发"应将"。
- **被吃到只剩最后 1 个 King 时**:进入"必须应将"模式——此后该 King 被将军必须立即解除;无法解除(将死)即判负。
- 将棋方只有 1 个王,**从开局起**就适用标准应将/将死规则。
- 王车易位:仅在该 King 仍为"普通子模式"或标准条件满足时允许;细节在实现时以"该 King 未被将军、路径无攻击、King 与对应 Rook 未移动过"为准。两个 King 各自独立判定易位权。

> 解释备注(已确认):"只有吃到只剩最后一个 King 时才必须应将"——即拥有 ≥2 王的一方不受将军约束,可弃车保帅式地丢一个王;只剩一王后回到标准国象规则。

## 6. 楚河汉界(纯视觉巧思,无玩法 buff)

- 第 5 行整行是**可正常通行的格子**,棋子可以停留、经过、在其上吃子。
- 视觉上画成**渡口**:横跨流水的木桥 / 踏脚石 + 水流动画,棋子踩上去有涟漪。目的:一眼看出"能踏过去",而非一堵墙。
- **不附带任何走法 buff**(用户已否决过河卒方案)。河界纯粹作为两种棋盘风格(木纹 / 黑白格)之间的视觉过渡带。

## 7. 打入(只有将棋方可以)

- 只有**将棋方**能打入(drops)。国象方吃掉的子直接移除出局,不能打入。
- 将棋方吃掉的**将棋子**:按标准将棋打入规则进手再落子(包含二步、打步诘、不能落在无法再走的格等限制)。
- 将棋方吃掉的**国象子**:转成五边形将棋造型进手;**打入后仍保留国象走法**(吃来的车落下去仍走车,马仍走马)。
  - 打入限制:不可落在该子永远无法再移动的格(如国象兵落在己方视角的底线);其余位置可落。
  - 打入的国象子默认未升变;国象兵打入后若走到对方底线仍可升变(选 后/车/象/马)。

## 8. 升变

- **将棋子**:进入敌阵最里 3 行触发标准将棋升变(可选/强制按标准规则)。
- **国象兵**:走到对方底线(行 1)升变为 后 / 车 / 象 / 马(玩家选择)。
- 国象的非兵子不升变。

## 9. 美术与皮肤系统

- 半盘材质:将棋侧木纹(榧木/桐木质感),国象侧黑白大理石格,河界流水动画。
- 棋子皮肤做成可切换的 skin pack,双方各 2–3 套:
  - 国象示例:经典 Staunton / 大理石雕 / 木雕。
  - 将棋示例:传统汉字体 / 书法体。
- 素材来源:CC0 免费站(Poly Haven 材质、OpenGameArt 等),统一调色。
- 打入的国象子统一加"五边形将棋底座"造型,与将棋手牌区视觉统一。

## 10. 大厅 / 房间 / 邀请(联网)

- 进入输入昵称(v1 不做完整登录/账号)。
- **大厅**:实时显示在线玩家列表 + 开放房间列表。
- **开房**:创建房间等待对手;或在大厅点某个在线玩家发**邀请**,对方接受后开局。
- **对局**:每步走子上报服务器,规则引擎权威校验后广播给双方;基础断线重连。
- 先选边(执国象 / 执将棋),或随机分配。

## 11. 构建顺序(玩法 + 美术并行推进)

1. 脚手架(client/server/shared)+ 共享规则引擎骨架 + 棋盘渲染(含材质)。
2. 完整走子/吃子/双 King 判定/打入/升变 —— 本地同屏先能完整玩通一局。
3. 大厅 / 房间 / 邀请 / 实时同步。
4. 皮肤切换 + 动画打磨 → Railway 部署。
