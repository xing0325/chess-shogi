# 大局选将(Taikyoku Draft)

从大局将棋(大局将棋,36×36,史上规模最大的将棋变体)的棋子里随机抽出一个卡池,双方按电竞赛事的 BP 流程禁用 / 选择棋子,再在 5×5 棋盘上布阵对战。

## 规则一览

| 项目 | 规则 | 依据 |
|---|---|---|
| 棋盘 | 5×5;先手(蓝方)底部两行 y=0,1,后手(红方)y=3,4 | 迷你将棋(5五将棋)尺寸 |
| 阵容 | 王将(固定,不参与 BP)+ BP 选出的 5 枚 | 王将按大局将棋原规则:任意方向最多 2 格(Betza `Q2`) |
| 卡池 | 每局从 205 种棋子里随机抽 24 种,双方都能看到 | Dota 2 Captain's Draft 的随机英雄池(28 个) |
| BP 顺序 | 共 20 步,见下表;禁 / 选都公开 | 英雄联盟职业赛 Tournament Draft |
| 唯一性 | 一种棋子只能被一方选走,禁用后双方都不能选 | 同上 |
| 步骤限时 | 联机每步 30 秒;超时:禁用 → 空过,选择 → 随机,布阵 → 随机 | Dota 2 队长模式的超时惯例 |
| 布阵 | 先手先放,双方轮流,每次 1 枚,6 枚全部放进己方底部两行 | 先手先选、后手后布,对应 LoL 蓝方先选、红方 counter-pick |
| 布阵约束 | ① 王将必须最先布;② 不能布下直接攻击对方王将的棋子,王将也不能放进对方火力范围;③ 某枚棋子放哪都会将军时,只要阵容里还有别的棋子能安全布下,就必须先布别的;④ 只有阵容里没有任何棋子能安全布下时才放宽(最后一步仍不能让先手开局无子可动) | 自定,见下文「布阵约束为什么这样设计」 |
| 先后手 | 蓝方先走。兜底:若开局时只有后手王将处于被攻击状态,改由后手先走(约千分之一) | 自定 |
| 走法 | 完全按大局将棋原规则:滑行、跳跃、限距跳越、钩行、狮子两步(含居喰)、跳越吃子 | 维基百科 Taikyoku shogi 词条 |
| 跳越吃子 | 大将 / 副将 / 飞将 / 角将 / 猛龙 / 飞鳄 可飞越并吃掉沿线所有等级更低的棋子(包括己方);不能飞越或吃掉同级及更高等级的棋子,因此吃不了王将 | 维基原文:"may only jump over or land on pieces of lower rank… impossible for range capturing pieces to capture the king" |
| 升变 | 升变区 = 对方底线;走入、走出或在区内移动时可选择升变;若不升变就再也无路可走,则必须升变 | 原规则未定论,采用迷你将棋惯例(5×5 上 11 行升变区没有意义) |
| 打入 | 无(大局将棋本身没有打入) | 原规则 |
| 胜负 | 将死或对方无子可动即胜;认输;联机掉线超过保留时间判负 | 将棋惯例 |
| 和棋 | 同一局面出现 4 次(千日手);300 手上限 | 将棋千日手 + 防止无限对局 |

### BP 顺序(20 步)

| 阶段 | 顺序 |
|---|---|
| 禁用 1 | 蓝 红 蓝 红 蓝 红 |
| 选择 1 | 蓝 · 红 红 · 蓝 蓝 · 红 |
| 禁用 2 | 红 蓝 红 蓝 |
| 选择 2 | 红 · 蓝 蓝 · 红 |

蓝方拿到第一选(最强棋子),红方用"连选两枚"和"最后一选"做针对性补强(counter-pick)。第二轮禁用由红方先手,这样双方都能根据对方已经选出的阵容做针对性禁用。

## 布阵约束为什么这样设计

布阵是公开轮流进行的,如果不加约束,可能直接摆出"开局即将军",极端情况下先手第一手就无路可走。用随机布阵做了统计:

| 规则版本 | 开局被将军 | 开局即判负 | 后手王将开局可被吃 |
|---|---|---|---|
| 只禁止将军(格子级放宽) | 12 / 500 | 2 / 500 | — |
| + 先布王将 | 2 / 500 | 2 / 500 | — |
| + 按棋子推迟布阵(当前) | 2 / 1500 | 0 / 1500 | 1 / 1500 → 由「后手先走」兜底 |

根源在于钩行者、奔鹫这类机动性极强的棋子:在空旷的 5×5 棋盘上,放在任何格子都能攻击到对方王将。所以放宽的粒度从"格子"改成了"棋子":先布能安全布下的棋子,等棋盘上有了遮挡,再布这些强力棋子。真人对局中玩家会主动规划,实际触发放宽的概率应该比随机布阵更低。

## 棋子数据从哪来、怎么校验

数据流水线在 `tools/taikyoku/`,产物是 `shared/src/taikyoku/pieces.data.ts`(自动生成,不要手改)。

1. `parse_wiki.py`:解析英文维基 Taikyoku shogi 词条,得到棋子总表(汉字名、英文名、升变关系)和每个棋子条目(Betza 记法、走法图、文字说明)。
2. `compile_betza.py`:把 Betza 记法编译成显式规则(slide / leap / jumpslide / hook / lion / igui / rangecap),再与同一词条里的走法图逐格比对。
3. `build_data.py`:合并成游戏数据。

校验结果:

| 项目 | 结果 |
|---|---|
| 与走法图逐格一致 | 227 / 230 |
| 走法图被截断、按原文确认 | 3(奮迅 Q3、獅鷹 角行部分、法性 后部分) |
| 按原文修正的记法笔误 | 2(金翅 vF → vR;教王 = 最多跳 3 格后八方向滑行) |
| 手工建模 | 奔鷲(Q + 限距跳越 + 居喰);其"沿线连吃"能力未建模 |
| 不进卡池 | 王将、太子(王族),淮鶏和老鼠(升变后的棋子名无法用 Unicode 表示) |
| 总计 | 301 种(含升变后),209 种基础棋子,205 种进卡池 |

TS 引擎与 Python 编译器的一致性由测试保证:`taikyoku.test.ts` 里,301 种棋子在空棋盘中心的可达格必须与 `reach.fixture.ts`(由已对过走法图的 Python 结果生成)完全相同。

重新生成数据(固定在维基版本 1378938316,2026-10-07;用这个版本从头跑,产出与仓库里的 `pieces.data.ts` 逐字节一致):

```bash
cd tools/taikyoku
curl -s "https://en.wikipedia.org/w/index.php?oldid=1378938316&action=raw" > taikyoku_en.wiki
python3 parse_wiki.py       # -> promotions.json, entries.json
python3 compile_betza.py    # -> compiled.json,并打印与走法图不一致的条目
python3 build_data.py       # -> ../../shared/src/taikyoku/pieces.data.ts
```

数据来自维基百科,遵循 CC BY-SA 4.0,生成文件头部已注明出处。

## 待定的设计问题

这些都属于产品判断,不是 bug,需要实际对局后再决定:

1. **平衡性**:205 种棋子强弱差距极大(步兵 vs 狮鹰),目前靠 BP 本身平衡。可以考虑给棋子分档(费用制),或在卡池里按档位抽取。
2. **先手优势**:蓝方先选、先布、先走,红方只多了 counter-pick 和最后一布。随机对局里双方胜率接近(1500 局:蓝 372、红 343、和 785),但随机走子说明不了真人对局的平衡,需要真人数据或引擎自对弈。
3. **升变区**:5×5 上只有底线一行,很多棋子几乎没机会升变,升变后的强力形态大多用不上。可以考虑扩大到两行。
4. **系列赛 BP**:可以加入 BO3 / BO5 的全局 BP(王者荣耀 KPL、LoL Fearless Draft:用过的棋子后续小局不能再选)。
5. **奔鹫的沿线连吃**未建模;跳越吃子的"等级"按维基的保守解释(不能吃同级或更高等级),另一种解释允许落在高等级棋子上吃掉,但维基指出这会严重失衡。
